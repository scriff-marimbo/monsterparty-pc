## 2. Static check

Every `jsr`, `jmp` and branch in the disassembly now lands on an instruction start (10,282 instructions checked). The only exception is the jump into RAM at $CF07 (above).

Every byte the CDL logged as executed is shown as an instruction, and no instruction sits on a byte the CDL logged as data. Getting there needed four repairs of damage from the over-read `b4_ItemHandlers` table:

- **b4 $AC86-$AE04:** two real `jsr`s and a `jmp` (the intro story loop, and a `jsr b4_DrawCutscenePicture`) had been split into bytes by fake labels. They are code again.
- **$E1AC:** a fake `brk` in zero filler, now a plain byte again.
- **b4 $BA20:** a fake label on `$FF` filler, removed.
- **$CBB6:** `InitSound`'s RTS, which is also byte 0 of `InitSound_DefaultsTable`, now shown as an `rts` line.

## 3. What is still not code

About 9,100 bytes in banks 4, 5 and 7 have never been read or executed and are not referenced by any code or table found. Most are data tables (per-type enemy and boss data, sound data) for content that wasn't played. A few short runs decode as clean code but nothing points to them; they are probably unused leftovers:

- b4 $8617, $8C62, $96C8 (52 instructions), $B09B
- b5 $8E9B, $9FE5, $A056, $A37B, $A51F, $A616, $AA17

Because the build includes every ROM byte, unreached data is harmless for a port. These leftovers only matter if something reaches them through a pointer stored in data (none found).
